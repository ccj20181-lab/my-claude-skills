一、什么是 Skill？为什么要写 Skill？简单来说，Skill 就像是给 Claude 装上的"插件"，让它学会特定的专长。想象一下：• 普通 Claude 像是一个通才，什么都知道一点• Skill 则像是给 Claude 配备的"专业工具包"，让它在特定领域变得专业写 Skill 的好处：1. 复用性强 - 写一次，可以反复使用，甚至分享给团队2. 上下文高效 - Skill 采用渐进式加载，只读取需要的内容3. 可维护 - 集中管理专业知识，便于迭代更新二、Skill 的"解剖学"：一个 Skill 由什么组成？2.1 基本结构skill-name/
├── SKILL.md          # 核心！必选，技能的主文档
├── scripts/          # 可选，可执行代码（Python/Bash等）
├── references/       # 可选，参考资料（API文档等）
├── assets/           # 可选，模板资源
└── LICENSE.txt       # 可选，许可证2.2 SKILL.md 的结构每个 SKILL.md 都分为三部分：---
name: skill-name # 必填！必须与目录名一致
description: 简短描述 # 必填！用第三人称
invocable: user # 可选，是否允许用户直接调用
license: 完整条款见 LICENSE.txt # 可选
---

2. 分析内容为什么？ 祈使句更直接、更易执行，减少歧义。原则 3：控制字数（黄金法则：5000 字以内）SKILL.md 推荐字数分级：技能类型推荐字数示例超简洁型< 250 字explaining-code (96 字)简洁型250-1000 字internal-comms (211 字)标准型1000-2000 字article-translator (1053 字)详细型2000-5000 字skill-creator (1660 字)超过 5000 字怎么办？• 把详细内容移到 references/ 目录• 把代码移到 scripts/ 目录• SKILL.md 只保留核心流程原则 4：渐进式信息组织信息密度递减的组织方式：1. 顶部（必读） - 使用场景、触发条件2. 中部（流程） - 具体工作步骤3. 底部（参考） - API 文档、详细说明示例结构：---
